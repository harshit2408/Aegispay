## AI models + IDs
**P0-16 / Q3 decided 2026-10-26, Dev B under the user's P0 closeout delegation:** use one provider, OpenAI, and one model for the initial implementation. The existing **$1.00 USD per invoice execution** cap remains; this is a selection decision, not a report of working inference or measured accuracy.

| Configuration | Exact value | Use (§10) |
|---|---|---|
| `LLM_PROVIDER` | `openai` | API process only (R22) |
| `LLM_MODEL_EXTRACT` | `gpt-6.1-sol` | A2: rendered invoice pages + text, schema-validated extraction |
| `LLM_MODEL_REASON` | `gpt-6.1-sol` | A1/A3/A7 runtime; A4/A5 standalone components and optional A6 remain integration work |

The selected model's [official page](https://developers.openai.com/api/docs/models/gpt-6.1-sol) was the model-selection reference. The current adapter uses Chat Completions with fixed model, output cap, default service tier, `store=false` and no tool definitions. A2/A3/A5/A6 have zero tools. The standalone A4 component invokes application-owned read tools from schema-validated JSON selections; it is not yet wired into the decision graph. All model output remains untrusted evidence; deterministic code owns amount, payee and gate decisions (R2/R3/R14).

Selection rationale: image input and structured output cover extraction and classification without a second integration. The [current model catalogue](https://developers.openai.com/api/docs/models) positions Sol between Astra's capability and Luna's cost. Sol is the initial quality-oriented choice within the agreed cap; cheaper Luna routing and additional providers add evaluation work and are deferred until §10.1 supplies evidence. Published capabilities do not establish accuracy on our invoices or injection cases.

Pricing checked **2026-10-26**: Standard, prompts ≤272K input tokens, **$2 input / $10 output per million tokens**. [Official pricing](https://developers.openai.com/api/docs/pricing) also lists caching, long-context and processing-tier rates; do not apply a cached/Batch/Flex discount to an ordinary request estimate. For illustration, four requests each using 40,000 billable input tokens and 8,000 total billable output tokens cost `4 × (40,000 × 2 + 8,000 × 10) / 1,000,000 = $0.64`. This is a planning example, not a token allowance or observed invoice cost; images and reasoning must be included in billable usage.

Implementation acceptance for §16: at most four model requests per invoice execution, including retries and A4 continuation requests; all share the $1 cap. The current provider adapter reserves a conservative maximum charge in PostgreSQL before HTTP and reconciles usage afterward. Unknown usage leaves the run halted. Fixed model/tier limits and conservative inclusive input bounds remain required; no cached-input discount is assumed. A2/A3 share a stable execution-derived budget ID, while A1 mandate authoring and A7 questions use separate bounded runs. A4/A5 future graph wiring must retain the invoice allowance; optional A6 needs its own bounded run. Local tests use synthetic responses; paid API access and the five-run held-out model evaluation remain unverified. Keep `LLM_API_KEY` in ignored local/service configuration only.

### P0-16 amendment: OpenRouter free model for the demo (2026-11-12, Dev A, user decision)

**Decision.** The user chose OpenRouter free models for the demo and the sandbox S1-S4 runs. Free tier = **demo only**; **synthetic PDFs only** (no real invoices, vendors or people); free providers may log and train on prompts. `openai`/`gpt-6.1-sol` stays the default and unchanged. This amends the 2026-10-26 single-provider decision; it is a selection and wiring change, not a claim of accuracy.

**Pinned model:** `nvidia/nemotron-3.5-super-vl:free`. Chosen on 2026-11-12 from the public `GET https://openrouter.ai/api/v1/models` listing (no key) as the `:free` model with `architecture.input_modalities` containing `image`, `supported_parameters` containing `response_format` and `structured_outputs`, and the largest context (1,000,000 tokens; max completion 131,072). Runners-up with the same capabilities: `dots-studio/dots-3-note-preview:free` (512k, expires 2026-12-31). Larger-context `thinkingmachines/inkling-2-small:free` lacks `response_format`. The adapter does not send `response_format`; the schema validation stays in our code (R14).

**Limits** (OpenRouter free tier): 20 requests/minute and 50 requests/day without a $10 lifetime credit top-up. A 429 or any provider error is a fail-closed `ProviderUnavailable` (sticky halt in `llm_budgets`, execution FREEZEs). Latency and quality are unmeasured except as recorded in docs/EVAL.md.

**Adapter (`backend/app/agents/provider.py`, allowlist `backend/app/agents/llm_allowlist.py`).** Env values only *select* an entry: `LLM_PROVIDER` (blank = `openai`) with `LLM_MODEL_EXTRACT`/`LLM_MODEL_REASON` (blank = that provider's reviewed default; the two must be equal), and `(provider, model, output cap)` must be a member of the code allowlist (the cap is per provider, see below). `openrouter` is additionally refused unless `DEMO_ENABLED=true` (which itself requires sandbox PayPal), so the free tier cannot run outside the demo. Each entry pins its own endpoint, so `LLM_API_KEY` is only ever sent to that provider (`https://openrouter.ai/api/v1/chat/completions` for `openrouter`). Unchanged for both providers: durable pre-HTTP `llm_budgets` admission, at most 4 requests per run, $1.00 cap with reserve `2 x input_bound + 10 x max_output` micros (free models are charged at the same conservative rate, so the ceiling is never looser than OpenAI's), `follow_redirects=False`, `trust_env=False`, `finish_reason == "stop"`, tool_calls rejection, strict integer usage validation. The pinned OpenRouter model is a reasoning model whose reasoning tokens count against the output cap (measured 880-975 completion tokens of a 1024 cap on a one-page invoice; one real S3 attempt failed closed on an uncertain provider outcome whose cause the adapter deliberately does not log, consistent with hitting the cap), so its allowlist entry uses a **4096** output cap (OpenAI stays 1024); the budget reserve uses the entry's own cap (`2 x bound + 10 x 4096` per request, at most four requests, still under $1.00). OpenRouter requests omit OpenAI-only fields (`store`, `service_tier`), use `max_tokens`, send `X-Title: AegisPay` and no user data in headers; null usage-detail objects count as 0 but missing or invalid prompt/completion usage still fails closed.

## Treasury Analyst (P3-11)

A7 uses the installed AG Studio 3.0.0 Agent Framework custom runner and the same fixed OpenAI `gpt-6.1-sol` adapter. One authenticated question selects a schema-validated execution list or status-count widget; the model receives only the delimited question and schema, with zero tools or execution records. Server code queries the read-only execution dataset using fixed status and 1/7/30-day filters, caps rows at 200 and renders server amounts. Unsupported widget selections produce an error; questions cannot grant write access. Controller/CFO sessions and CSRF are required; requests are limited to five per operator per minute. Each question owns a separate TokenOps run with durable pre-HTTP admission, the existing $1/four-request ceiling and no retries. Local verification uses synthetic completions; no live A7 model quality or provider access is claimed.
