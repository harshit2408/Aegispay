Docker Compose v5.6.1 interpreted an empty assignment followed by spaces and an inline comment as the literal comment value. PR #33's worker failed with "Invalid service configuration fields: audit_anchor_repo" even though the placeholder appeared empty. The earlier Node fixture helper removed comments and then injected every template value into the child environment, so it masked the raw-file parsing behavior.

Keep comments for empty public placeholders on their own preceding lines, followed by an exact KEY= assignment. The fix covers six affected fields in .env.example and the matching PRD section 7 example. Preserve strict settings validation and the API/settlement environment split; do not special-case comment text as a valid repo or token.

Regression tests must remove known template keys from the child environment and let actual Docker Compose parse the committed public template. The resumed run passed all 26 Node tests without skips, then passed a fresh production Postgres/API/worker stack built from a tracked archive plus the named template overlay. Health, restricted environment isolation, empty optional anchor settings and graceful worker exit were checked; only that run's containers/network/volume were removed. No live provider request or secret-file access occurred. docs/SESSION_LOG.md records the exact verification boundary; the checklist alone owns task state.
