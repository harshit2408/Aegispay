2026-10-26 IST, Dev B P0-20 closeout. SPIKE-11's published probe (PR #2 a7cc8a4) could return PASS when an error only mentioned the original batch ID, and it never GET-verified the original command. Five offline regressions reproduced those false positives. Require a structurally valid sandbox duplicate link, extract the ID without following the URL, then GET on the configured base and compare original batch ID, sender batch ID, exactly one item, sender item ID, recipient type, receiver, amount and currency. Preserve unconditional failure if a retry creates another batch. The original real sandbox run remains EMAIL-only: HTTP201 then duplicate400 USER_BUSINESS_ERROR with SENDER_BATCH_ID/details[].link; list404 and reporting403. PAYPAL_ID duplicate shape and retention duration remain unconfirmed. Offline probe hardening is not evidence of working product crash recovery.
