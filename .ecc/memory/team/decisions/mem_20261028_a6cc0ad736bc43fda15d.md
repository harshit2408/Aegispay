2026-10-28, Dev B. P2-26 extends the existing audit snapshot/freshness lesson and restricted-login decision. The implementation and setup contract are in docs/AUDIT.md; PRD R21-R23 remains authoritative.

Keep unsigned queue producers free of the global chain advisory lock. A producer can already hold a PO lock while a reconciler takes that PO lock after a transition; adding the audit lock to producers reverses lock order and deadlocks them. The consumer alone takes the chain advisory lock and SHARE ROW EXCLUSIVE on audit_queue, waits for existing inserts, reads fresh committed rows, and atomically signs/deletes its batch. It does not lock money records or hold database transactions across Git I/O. Use enqueue_event for producers; direct append_event belongs to the consumer.

The latest externally fetched audit-anchors checkpoint supplies trust; DB audit_anchors rows are receipts only. Git uses fresh repositories without checkout, disabled hooks/helpers, a sanitized environment, normal non-force pushes and a dedicated optional repository token. Verify the complete global anchored prefix before execution filtering. Missing or corrupt external history refuses export; HMAC-only mode is explicit when no repo has ever been configured. Confirmed integrity failure persists the halt flag in a separate transaction before worker stop, including startup.

Deployment must verify migration 0007's settlement queue INSERT/sequence grants, preserve a securely generated HMAC key of at least 32 characters across restarts, and configure the public anchor repository and optional dedicated write token privately in settlement only. Never copy signing material into the API. Authenticated HTTP export and case downloads remain a separate integration seam. Local bare-Git/Postgres tests do not prove hosted publication or branch protection. Task state stays only in docs/CHECKLIST.md.
